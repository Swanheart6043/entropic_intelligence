

# 云端连接配置

新项目使用完整 URL：

```ini
[platform]
websocket_url = wss://cloud.example.com/websocket/robot/{sn}
http_base_url = https://cloud.example.com/robotboot
rtsp_base_url = rtsp://media.example.com:2554
tls_verify = true
ca_cert_path = /etc/ssl/certs/project-cloud-ca.pem

cloud_outbox_dir = /var/lib/patrol_robot_h1/cloud_outbox
cloud_outbox_max_jobs = 512
cloud_outbox_max_megabytes = 256
cloud_outbox_capture_ttl_hours = 24
cloud_outbox_dead_letter_ttl_hours = 168
cloud_outbox_dead_letter_max_jobs = 128
cloud_outbox_dead_letter_max_megabytes = 32
cloud_outbox_alarm_reserved_jobs = 64
cloud_outbox_alarm_reserved_megabytes = 32
cloud_outbox_cleanup_interval_seconds = 60
cloud_outbox_orphan_grace_seconds = 600
```

## 长期运行时的 outbox 保留策略

- 启动时、运行期间每 60 秒检查一次；容量不足时立即尝试回收。清理不依赖重启或云端连接。
- 普通抓拍超过 24 小时丢弃；满额时优先回收死信，然后淘汰最旧且未在发送中的普通抓拍。每次丢弃都有 INFO 日志及进程内累计计数。
- 告警优先发送，默认预留 64 个任务和 32 MiB，普通抓拍不能使用这部分配额。待发送告警没有自动过期或压力淘汰；如果容量已被告警、发送中的事件或无法删除的文件占满，仍返回带用量信息的 `outbox_full`，业务端会记录入队失败。
- 死信元数据和配套图片一起保留，最长 7 天、最多 128 个事件、最多 32 MiB；任一上限触发回收最旧死信。总体容量紧张时提前回收死信。死信预算包含在总预算内，并非额外容量。
- 无关联元数据的图片以及 `.json.tmp` / `.bin.tmp` 超过 10 分钟回收。有效死信图片及发送中的事件受保护。
- 容量统计包括目录内的普通文件（包括 `.failed`、`.sent`、`.tmp`），待发送元数据额外按至少 8 KiB 预留重试及图片 URL 检查点空间。原子替换写入会产生短暂的临时文件开销，配置限额不等同于文件系统硬配额。
- 总条数/容量、TTL、死信限制、清理周期、孤立文件宽限期必须为正；告警预留可以为 0，但必须小于总限制。旧配置未显式设置预留时，按 `min(64, 总条数/4)`、`min(32, 总 MiB/4)` 计算，兼容较小队列。

配置由 `/etc/patrol_robot_h1/config.ini` 启动时加载，修改后重启 `web_gateway` 生效。已有 `.json` / `.bin` / `.failed` 文件直接兼容，无需清空目录；首次启动会按上述策略清理已有的过期数据。

`{sn}` 在加载配置时替换为设备序列号。协议由 URL 明确指定，不会在 HTTPS/WSS 失败时自动降级到明文协议。

使用系统公共 CA 时可以留空 `ca_cert_path`，但生产环境应保持 `tls_verify=true`。私有 CA 项目配置对应的 CA 文件。

旧项目的 `wss_server_ip`、`wss_server_port`、`http_server_ip`、`rtsp_server_ip` 等拆分字段仍可由程序读取，但只作为升级过渡。升级时执行：

```bash
sudo python3 scripts/migrate_platform_urls.py --config /etc/patrol_robot_h1/config.ini
```

迁移脚本会生成三个完整 URL、删除旧拆分字段，并保留一份 `.pre-platform-url-migration.bak` 原始配置备份。脚本可重复执行。
