# web_gateway测试思路

## outbox / WebSocket 回归测试

在已安装项目 C++、Boost、OpenSSL、nlohmann-json、spdlog 依赖的构建环境执行：

```bash
make -C coordinator/services/web_gateway test
```

`cloud_outbox_test` 使用临时目录，覆盖容量与元数据统计、告警预留、最旧抓拍淘汰、发送中保护、满队列幂等检查、逐条退避、URL 检查点和重启恢复、死信与孤立文件清理、删除失败恢复。

`run_websocket_tests.py` 在回环地址启动临时 TCP 服务，覆盖无连接发送、无业务 ACK 的正常本地写入、下行回调回复、防止回调线程阻塞、连续握手失败重连、对端停止读取导致的写入超时、连接 RST 后重连。断网场景同时检查 INFO 失败日志，测试不连接实际云端。

部署到机器人后还需现场检查断开/恢复路由器时的日志和补传，并观察 `云端outbox状态` 中的任务数及容量是否下降。普通抓拍满额淘汰和过期清理均会打印具体原因。
